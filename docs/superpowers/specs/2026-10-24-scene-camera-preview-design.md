# 应用与 Blender 场景/机位预览

## 已批准的目标与范围

用户已批准：设置场景数和每场景视角数后，在应用内及「在 Blender 中查看」打开的 Blender 中都能切换场景、视角，检查相机实际构图和可旋转的场景总览；随后指定使用 flow 的 build-verify 实现与独立验收。

- 场景编号和视角编号按项目的 `scene_count` / `views` 定义；UI 从 1 计数，采样器从 0 计数。
- 固定模式的视角对应完整固定机位列表；随机模式保留所有区域及生产分配顺序，不能把配置缩成单个机位/区域或单场景。
- 两个视图使用同一个完整候选（布局、相机内外参、灯光、材质、HDRI、该视角的遮挡物），不另造预览采样器。总览显示当前相机位置/朝向；不要求一次显示全部场景或所有机位。
- Blender 有侧栏预览面板：场景/视角选择、更新候选、相机视图、场景总览、渲染预览，以及当前编号、种子、相机和相关场景参数的只读摘要。
- 默认几何预览不要求 Cycles GPU/降噪可用；点击渲染预览才运行既有严格 GPU/降噪检查。失败显示操作建议并保持几何预览，不开启 CPU 回退。
- 场景按需更新，网格复用，不按 `scene_count × views` 预先创建所有对象/场景。采样有界，失败显式提示；快速切换不会把旧结果显示为新选择。
- `候选预览 · 未经像素遮挡验收` 为明确提示。正式运行会进行像素验收并可能重试，不保证最终接受的姿态和初始候选永远相同。
- 编辑器中改变预览编号/观察角度不修改科学配置或 dirty 状态。若保留独立预览种子，必须随候选一起传给 Blender，用同一有效配置重放后续编号。
- 场景科学参数仍在原应用编辑；不实现从 Blender 反向同步。现有 `.blend`/应用启动链路在本机仓库与资源存在时工作；不做独立分发插件或可移植资产打包，也不偷偷启用 Blender 自动运行脚本权限。

## 现状与实现决策

- `bproc_ui.preview._Search` 固定调用 `sample_scene(..., 0)`，`refresh` 将配置缩到单机位/区域和 `scene_count=1`，因此不仅没有场景选择，无遮挡分类和区域分配也可能不等于生产语义。
- `MainWindow` 有已有总览、独立相机窗口和底部机位栏；直接扩展这些现有控件，沿用 Qt 主题，不做外观重设计。底栏显示「场景 [1 / N] 视角 [1 / M] 来源 [只读实际来源] 预览种子 [seed] 刷新」。
- `tools/blender_view.py` 只保存一个当前候选；`BlenderBackend.apply` 使用单帧相机。增加真正的预览会话，不把时间轴当成已经烘焙的全部场景。
- 尽量复用 `BlenderBackend.prepare/apply` 和现有原生 Blender/BlenderProc 对象；几何初始化与渲染初始化分开。渲染入口仍默认严格模式。先前未提交的 OPTIX 修复必须保留在严格模式中，几何预览采用显式独立入口/参数。
- 建议新增聚焦模块 `bproc_core/preview.py` 放无 Qt/bpy 的有界候选查询，`bproc_runtime/blender_preview.py` 放 Blender 会话/侧栏；不扩大成通用任务系统。
- Blender 的 Python 导入有环境限制：BlenderProc 先于 numpy 导入；必须验证 GUI `--view-only` 路径能获得源码和所需依赖，而不只在后台构建路径成功。面板注册和会话初始化不得破坏用户无关场景或改动 Blender 安全首选项。

## 验收标准

AC-1 生产一致性：至少 2 场景 × 3 随机视角、多个区域及 2 个固定机位的测试。按完整配置与指定种子运行 `sample_scene` / `propose_candidate`，比较完整 `candidate_to_dict`；场景编号、视角编号、区域/机位、布局、相机、光照、遮挡分类一致。不缩小场景数。预览不改变配置/dirty。

AC-2 应用交互：主窗口能选择任一合法场景和视角，固定模式第二机位为 view_index=1 而非 0；总览与相机窗口更新为同一候选，来源与编号准确。场景数减少/模式变化会限界或明确清空；空草稿不启动无效构建。保留异步失效隔离、关闭清理、重载安全，不接受晚到结果。

AC-3 快照交接：从应用传到 Blender 的初始候选不被重新随机化；有效预览种子和完整配置一起传递。传输含当前场景/视角与必要路径/数据，后续重访该编号得到相同候选；源 YAML 不被修改。

AC-4 Blender 可操作：真实 Blender 4.2 中注册面板与操作符，从初始候选切换到另一视角、另一场景，再返回。实时相机矩阵/K、目标及遮挡物变换、光照等与共享候选一致。切换相机/总览确实改变 VIEW_3D 状态而非只改标签；显示当前相机位置/朝向及只读参数。切换不为每个场景累积重复网格/对象；注册重复调用及会话关闭不遗留重复注册/活动工作。

AC-5 几何/渲染分离：非 OPTIX 后端 + OPTIX 降噪能用显式几何预览打开/切换；不调用 `configure_gpu` 或降噪渲染初始化。请求渲染预览时非法组合给中文修复提示并保留几何视图。默认正式渲染、导出、preflight 与严格 `prepare_scene` 的现有拒绝规则继续通过测试，没有 CPU 渲染/降噪回退。

AC-6 有界与诚实状态：两端明显标注候选尚未经像素验收；查询上限不随场景总数乘法膨胀，不预生成全集。查询失败/超时不冒充成功，旧场景不会标成新编号。必要的项目依赖缺失提供可定位消息。

AC-7 证据与使用说明：全量 unit/Qt 测试通过；新增真实 Blender smoke 验证 AC-4/5（不能仅用 mocks 或静态 AST 代替）并留下可复跑命令/退出码。默认使用本机已装 Blender，不安装依赖/变更系统环境。更新 docs/usage.md 描述应用控件、Blender 面板入口、几何/渲染预览差别和候选边界；记录实际验证与未验证范围，不能声称未运行的硬件渲染/人工 GUI 验收。

## 非目标与变更边界

不修改数据集采样规则、不做渲染队列、不做 Blender 参数回传、不批量复制所有场景、不增加第三方依赖、不重写 UI、不改版本/标签、不提交或 push。
已有未提交代码包括 OPTIX 配置错误前置提示及测试，不能丢失。允许为新批准的几何预览调整原先依赖默认渲染查看的 UI 测试，必须增加严格模式继续拒绝的对应证据，不得通过删除测试隐瞒回归。
